# Search Language Rules (Local-Language First)

When researching a destination via `WebSearch` or `WebFetch`, **search in the destination's local language first**, then supplement with English/the user's language as needed. Local-language queries surface official sites, current prices, and recent updates that English-only queries miss.

## Why

- **Official sites are written in the local language.** Japan attraction sites publish hours, prices, and closures in Japanese first; English pages lag or omit details.
- **Local prices are accurate.** Tourist-aggregator English pages quote stale or marked-up prices.
- **Recent info surfaces faster.** Local bloggers and news cover seasonal events, closures, and new openings months before English coverage.
- **Local SEO ranks local content higher** for local queries — the top results are the ones locals actually use.

## How To Apply

1. **First pass — local language.** Run the core discovery searches (top attractions, hours, prices, official site, recent news) in the destination's primary language.
2. **Second pass — English.** Cross-check with English queries for anything the local-language pass missed, plus aggregator/booking platforms (Klook, GetYourGuide, TripAdvisor) that index English well.
3. **Third pass — user's language.** If the user is a Chinese speaker going to Japan, also run Chinese-language queries for trip reports (小紅書, PTT, Mobile01) — these match the user's planning style and surface peer reviews.
4. **Fetch official sites in their native language**, even if you summarize back in the user's language. The native-language page is the source of truth for hours and prices.
5. **When linking to the user**, prefer pages in the **user's** conversation language for tutorials and how-tos (per phase-4 transit rule). Use local-language links only when the user reads that language or when no equivalent exists.

## Common Mistakes

- ❌ Searching `"Tokyo attractions 2026"` only — gets aggregator listicles, not official info.
- ❌ Using `{destination}` as a placeholder in English when the destination has a native name (use 東京 not Tokyo for Japanese queries).
- ❌ Trusting English price quotes from third-party blogs — verify on the official local-language page.
- ❌ Skipping local language because "the user doesn't read it" — search results inform *your* recommendation; you summarize back in the user's language.
